# 한국어 대사 — 발음·억양·표기

> **실측 확인(2026-09-29)**: 프롬프트의 한국어 대사가 **그 문장 그대로** 발음됐다.
> 이 프로젝트에서 가장 중요한 확인 사항이다.

---

## 1. 실측 결과

```
프롬프트:  수아가 낮게 말한다: "여기서 뭐 하는 거예요?"
결과 오디오: [3.89-5.89] 여기서 뭐 하는 거예요?    (언어판정 ko, 확률 1.0, 길이 10.01초)
```

→ **한국어 대사를 프롬프트에 직접 써도 된다.** 로마자 변환·더빙 대체가 필수는 아니다.

---

## 2. 대사 문형

```
[이름]가 [말투] 말한다: "[한국어 문장]"
```

| 규칙 | 이유 |
|---|---|
| **한국어로 그대로 쓴다** | 로마자로 쓰면 발음이 무너진다 |
| **한 문장만** | 10초에 두 마디는 안 들어간다 |
| **말투를 붙인다** (`낮게`, `조용히`, `화내며`, `빠르게`) | 그대로 연기가 된다 |
| **대사는 프롬프트 앞쪽**(⑤ 동작의 맨 앞)에 | 뒤에 있으면 장식으로 취급된다 |
| 대사가 없으면 | `대사 없음, 내레이션 없음.` |

### 화자 지정

- 여러 명이 나오면 **누가 먼저 말하는지** 명시: `The woman speaks first, … in Korean, fast delivery:`
- 한 명만 말하면 나머지에게: `Manbok does not speak.`
- 대사가 끝난 뒤 반응: `He goes very still.`

---

## 3. 억양·속도 어휘

| 한글 의도 | 프롬프트에 쓸 표현 |
|---|---|
| 차갑게 | `cold, flat delivery` |
| 비웃으며 | `sneering, sharp` |
| 낮게 | `low, quiet` |
| 빠르게 | `fast delivery` |
| 떨리며 | `shaking, barely holding it together` |
| 체념하며 | `tired, matter-of-fact` |
| 소리치며 | `shouting, cracking` |

**한국어 대사 옆에 반드시 `in Korean` 을 쓴다.** 그리고 톤을 함께 쓴다.

---

## 4. 길이 감각 (10초)

| 대사 길이 | 가능 여부 |
|---|---|
| 10자 이하 | ✅ 여유. 반응까지 나온다 |
| 15~25자 | ✅ 이것이 표준 (예: `다 먹었는데 맛이 없네요, 이 나이 먹고 장사 그렇게 하세요?`) |
| 30자 이상 | ⚠️ 3비트 중 2개를 대사가 먹는다 |
| 두 문장 | ❌ 한 문장으로 줄이거나 샷을 나눈다 |

---

## 5. 지시문 언어 규칙

| | 상태 |
|---|---|
| **한국어 지시문 + 한국어 대사** | ✅ **실측 검증됨** (위 전사) |
| **영어 지시문 + 한국어 대사** | ⚠️ **미검증** — 같은 장면으로 A/B 비교 후 결정 |
| 한 프롬프트에 두 언어를 섞기 | ❌ 하지 않는다 (대사만 한국어) |

스킬은 지시문 언어를 **고정하지 않는다.** 프로젝트에서 하나를 골라 `project-card.json` 에 적고 유지한다.

---

## 6. 안 될 때의 순서 (폴백)

1. **대사를 짧게** 자른다 (한 문장 유지)
2. **말투 지시를 바꾼다** (`낮게` → `조용히, 천천히`)
3. **입모양이 안 보이는 샷**으로 바꾼다 (뒷모습·손 클로즈업) — 대사는 후반 합성
4. 그래도 안 되면 **후반 더빙**: 대사 없이 생성 → 후반에 한국어 음성 + 자막

> **후반 합성은 실패가 아니라 선택지다.** 화면 글자와 같은 원칙 — 한글은 후반이 안전하다.

---

## 7. 강의에서 말할 것

- 대사가 **들리는 것**과 **입이 맞는 것**은 다르다. 결과를 보고 판정한다(`judgement.jsonl`).
- 같은 대사를 3번 다시 만들면 **크레딧이 3배**다. **이미지 단계에서 구도를 잡고** 영상은 한 번에 간다.
- 발음이 계속 어긋나면 **프롬프트 문제가 아니다** — 대사가 길거나 샷이 와이드다.
